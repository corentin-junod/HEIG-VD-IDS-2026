Projet - Randonnées personnalisées

Contexte

Swisstopo diffuse le réseau de chemin de randonnées dans le modèle topographique swissTLM3D, sous forme de couche cartographique (images) et sous forme de données (géométries et attributs) accessibles par des services en ligne.

L'objectif du projet est de réaliser une application web qui, à partir d'un point de départ choisi en cliquant sur la carte, calcule des boucles de randonnée : des itinéraires qui partent du point cliqué et y reviennent, dans un temps donné. Par exemple :

  • la boucle la plus longue possible en 3 heures ;
  • la boucle avec le plus de dénivelé possible en 3 heures ;
  • les mêmes boucles, mais sans passer deux fois par le même chemin.
Pour y arriver, l'application devra récupérer les chemins et les altitudes auprès des services de la Confédération, les convertir en objets JavaScript à partir de leur modèle INTERLIS, en faire un graphe, puis y chercher les meilleurs tracés.

Organisation

Ce guide découpe le projet en étapes. Chaque étape indique son objectif, mais pas la manière de l'implémenter : c'est à vous de concevoir et d'écrire le code. Certaines informations (adresses des services, constantes, signatures de fonctions) vous sont données précisément, il vous est conseillé de les respecter.

Les documentations citées font partie du projet : il est attendu que vous les lisiez. Les slides du cours (en particulier Node.js & Vite et OpenLayers) contiennent également une grande partie de ce dont vous aurez besoin.

Étape 1 : Mise en place du projet

Objectif : disposer d'un projet Node.js + Vite qui affiche une carte OpenLayers de base dans le navigateur.

  • Si ce n'est pas déjà fait, installez Node.js (version LTS) : https://nodejs.org/
  • Créez le projet en suivant la mise en place d'un projet OpenLayers de base, telle que décrite dans la documentation officielle : https://openlayers.org/doc/quickstart.html. Lisez cette page en entier : elle explique le rôle de chaque fichier du projet créé.
  • Démarrez le serveur de développement et vérifiez qu'une carte du monde s'affiche dans votre navigateur.
  • Prenez le temps de comprendre le contenu des fichiers package.json, index.html, main.js et style.css, ainsi que le rôle de Vite (documentation : https://vite.dev/guide/).
  • Une fois la base de code en place, créez un dépôt sur GitHub et placez-y votre code. Tous les membres du groupe pourront récupérer le code sur leur machine

Étape 2 : Afficher les chemins de randonnée

Objectif : afficher la carte en projection suisse EPSG:2056, avec un fond de carte swisstopo et, par-dessus, la couche WMTS des chemins de randonnée de la Confédération.

  • Consultez la liste des couches WMTS diffusées par la Confédération, et trouvez celle des chemins de randonnée (en allemand : Wanderwege). Notez son identifiant et le format de ses tuiles.
    • Documentation du service WMTS : https://docs.geo.admin.ch/visualize-data/wmts.html
    • Fichier GetCapabilities des couches (qui en donne la liste complète) : https://wmts.geo.admin.ch/EPSG/2056/1.0.0/WMTSCapabilities.xml
    • Les couches peuvent aussi être explorées visuellement sur https://map.geo.admin.ch
  • Configurez OpenLayers pour qu'il utilise la projection EPSG:2056, comme montré dans les slides. Pour l'étendue de la carte, vous pouvez prendre 
    [2420000, 1030000, 2900000, 1350000]
  • Les tuiles Swisstopo en EPSG:2056 suivent leur propre grille de tuilage, qu'il faut décrire à OpenLayers. Ses paramètres sont :
    • Origine de la grille (coin supérieur gauche) : [2420000, 1350000]
    • Résolutions (en mètres par pixel), du niveau 0 au niveau 28 : 
      [4000, 3750, 3500, 3250, 3000, 2750, 2500, 2250, 2000, 1750, 1500, 1250, 1000, 750, 650,
 500, 250, 100, 50, 20, 10, 5, 2.5, 2, 1.5, 1, 0.5, 0.25, 0.1]
    • Adresse des tuiles d'une couche (à compléter avec l'identifiant et le format de la couche) : 
      https://wmts.geo.admin.ch/1.0.0/{identifiant}/default/current/2056/{z}/{x}/{y}.{format}
    • Attention : la couche des chemins de randonnée n'a pas de tuiles au-delà du niveau 26. Cherchez dans la documentation de la source OpenLayers que vous utilisez comment l'indiquer, pour que la couche reste visible quand on zoome davantage.
  • Ajoutez sous les chemins un fond de carte swisstopo. Choisissez-le de manière à ce que les chemins (jaunes, orange et rouges) restent bien lisibles.
  • Centrez la vue sur la Suisse, par exemple en [2600000, 1180000].

Résultat attendu : une carte de la Suisse sur laquelle, en zoomant, les chemins de randonnée apparaissent par-dessus le fond de carte.

Étape 3 : Réagir aux clics sur la carte

Objectif : savoir où l'utilisateur a cliqué. Le clic servira plus tard à choisir le point de départ des tracés.

  • Ajoutez un événement qui réagit au clic sur la carte. Les slides OpenLayers et la section Fires de la documentation de la Map vous indiquent comment faire : https://openlayers.org/en/latest/apidoc/module-ol_Map-Map.html
  • Ajoutez sur la page un panneau latéral dans lequel vous pouvez afficher des informations. Vous pouvez le faire par exemple en ajouter un nouveau bloc "div" dans le code HTML et en ajoutant le CSS nécessaire
  • À chaque clic, affichez les coordonnées du point cliqué dans un élément de la page (pas seulement dans la console).
  • Vérifiez que les coordonnées obtenues sont bien en EPSG:2056 : elles doivent ressembler à 2600000, 1200000 (environ Berne), et non à des degrés.
  • Réfléchissez à l'organisation de votre code : le code qui concerne la carte et le code qui décide quoi faire d'un clic n'ont pas forcément leur place au même endroit.

Étape 4 : Récupérer des altitudes

Objectif : écrire une fonction qui demande au service de profil de la Confédération l'altitude d'une liste de points. Elle servira à connaître le dénivelé des chemins.

  • Adresse du service : https://api3.geo.admin.ch/rest/services/profile.json
  • Documentation : https://docs.geo.admin.ch/access-data/get-elevation-profile.html
  • Paramètres utilisés dans le projet :
    • geom : la ligne dont on veut le profil, sous forme de texte GeoJSON (une géométrie de type LineString)
    • sr : la projection des coordonnées, ici 2056
    • nb_points : avec la valeur 2, le service renvoie exactement un point de profil par point de la ligne, dans le même ordre
  • Exemple de requête, que vous pouvez ouvrir directement dans votre navigateur : 
    https://api3.geo.admin.ch/rest/services/profile.json?geom={"type":"LineString","coordinates":[[2568089.6,1130826.9],[2567800,1130500],[2567500,1130300]]}&sr=2056&nb_points=2
    Observez la réponse : quelles informations contient-elle ? Dans le projet, on utilisera l'altitude du modèle DTM2.
  • Avec une requête GET, si la requête contient trop de points, l'adresse de la page devient alors trop longue et le service répond par une erreur 414. Pour éviter ce problème, le service accepte aussi des requêtes POST, avec les mêmes paramètres placés dans le corps de la requête (Content-Type: application/x-www-form-urlencoded). Voir la documentation de fetch pour envoyer une requête POST.

    Exemple : la requête GET suivante (vers un service fictif) 
    const response = await fetch("https://example.com/api/service?nom=Dupont&texte=" + encodeURIComponent("Bonjour à tous"));
    s'écrit en POST de la manière suivante : 
    const response = await fetch("https://example.com/api/service", {
    method: "POST", // méthode HTTP utilisée
    headers: {"Content-Type": "application/x-www-form-urlencoded"},
    // Corps de la requête : les mêmes paramètres qu'après le "?" de la requête GET, sous la forme nom=valeur, séparés par des &, et encodés avec encodeURIComponent
    body: "nom=Dupont&texte=" + encodeURIComponent("Bonjour à tous")
});
    La réponse se traite ensuite exactement comme pour une requête GET (response.ok, response.json(), etc.).
  • Dans votre code, implémentez la fonction suivante :

 * Demande au service de profil l'altitude de chaque point.
 * @param {Array} coordinates - tableau de coordonnées [x, y] en EPSG:2056, par exemple [[2568089.6, 1130826.9], [2567800, 1130500]]
 * @returns {Promise} promesse d'un tableau de nombres : l'altitude (DTM2) de chaque point, dans le même ordre
 */
async function getAltitudes(coordinates){
    // Contenu de la fonction
}
    Construisez vous-même la requête à partir des paramètres ci-dessus.
  • Pour tester, l'appel suivant : 
    getAltitudes([[2568089.6, 1130826.9], [2567800, 1130500], [2567500, 1130300]])
    doit donner : 
    [790, 773.9, 768.8]

Étape 5 : Récupérer les chemins de randonnée

Objectif : écrire une fonction qui récupère, auprès du service identify de la Confédération, tous les chemins de randonnée situés dans un rectangle. Pour le moment, la fonction renvoie simplement les résultats tels que le service les fournit.

  • Adresse du service : https://api3.geo.admin.ch/rest/services/api/MapServer/identify
  • Documentation : https://docs.geo.admin.ch/access-data/identify-features.html
  • Paramètres utilisés dans le projet :
    • layers : all: suivi de l'identifiant de la couche des chemins de randonnée (le même qu'à l'étape 2)
    • geometryType : esriGeometryEnvelope (on interroge un rectangle)
    • geometry : le rectangle, sous la forme xMin,yMin,xMax,yMax
    • mapExtent : le même rectangle
    • imageDisplay : 1000,1000,96
    • tolerance : 0
    • sr : 2056
    • returnGeometry : true et geometryFormat : geojson, pour recevoir la géométrie des chemins
    • limit et offset : voir ci-dessous
  • Attention : pour chaque appel, le service renvoie au maximum 200 résultats par requête (paramètre limit). Pour obtenir les résultats suivants, s'il y en a plus que 200, il faut changer l'offset. Par exemple, si vous faites une requête et qu'elle retourne 200 résultats, il y en a peut-être plus. Pour voir les résultats suivants, il vous faudra faire une seconde requête avec offset=200 pour obtenir les résultats 200 à 400 (ou moins s'il y a moins de 400 résultats).

Étape 6 : Modèle INTERLIS et classes JavaScript

Objectif : représenter les chemins de randonnée par des objets JavaScript, en partant de la description officielle des données, et non de ce que le service renvoie.

  • Les données des chemins de randonnée sont décrites par le modèle INTERLIS swissTLM3D_ili2_V2_3, disponible dans le dépôt de modèles de la Confédération :
    • Dépôt de modèles : https://models.geo.admin.ch
    • Fichier du modèle : https://models.geo.admin.ch/Swisstopo/swissTLM3D_ili2_V2_3.ili
  • Dans ce modèle, un tronçon de chemin de randonnée est un objet de la classe TLM_STRASSE du topic TLM_STRASSEN. Lisez sa définition, ainsi que celle de tout ce qu'elle utilise : la classe dont elle hérite, ses domaines de valeurs (énumérations), et le type de sa géométrie (D_POLYLINE, dont les sommets sont de type HKoord).
  • Créez une ou plusieurs classes JavaScript, chacune dans son module, qui reprennent ce que le modèle INTERLIS indique pour un tronçon de chemin de randonnée. Quelques questions pour vous guider :
    • Quels attributs du modèle sont utiles au projet ? Lesquels le service de l'étape 5 fournit-il réellement, et sous quel nom ?
    • Comment représenter en JavaScript une énumération INTERLIS, et que faire si une valeur reçue n'en fait pas partie ?
    • Que faire d'un attribut obligatoire (MANDATORY) absent, ou d'une géométrie invalide ?
    • Comment représenter un sommet de type HKoord ? Le service de l'étape 5 renvoie-t-il toutes ses composantes ? Comment compléter celles qui manquent avec l'étape 4 ?
    • Le modèle autorise des arcs de cercle dans les lignes. Dans ce projet, on considère que les chemins sont uniquement composés de segments droits.
    • Les objets doivent-ils pouvoir être modifiés après leur création ? Pensez à l'encapsulation et à l'immutabilité vues en cours.
  • Écrivez une fonction qui convertit un résultat de l'étape 5 en objet de votre classe, et vérifiez que les chemins du second rectangle de l'étape 5 sont tous convertis sans erreur.
